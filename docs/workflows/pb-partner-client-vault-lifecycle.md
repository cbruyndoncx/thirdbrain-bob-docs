# Partner Client Vault Lifecycle

*Client vault installed, structured, operating on cadence, refreshed quarterly with a governance report, and carried through an explicit renew / expand / offboard decision*

> You installed it. Nine months later, nobody knows if it is still used.

| | |
|---|---|
| **Area** | Sales & Clients |
| **Time savings** | Typical run: Stage 1-2 in the first week; stages 3-6 loop quarterly; stage 7 at term end — runs across the full engagement |
| **Try it** | "Partner signs a new SMB client for a BOB-powered service, or an existing client vault reaches its quarterly refresh or renewal point" |
| **Compounding** | Each run refines templates and context — 0 automated steps improve with accumulated data |
| **Frequency** | Per trigger event |

## Inputs

- 🏢 Client name and `client-id`
- 📅 Retainer tier sold (Operate / Govern / Scale) and term dates
- 🏢 The client's binding constraint (from discovery) → selects the core playbook bundle
- 📋 Refresh cadence (default quarterly)

## Outputs

- 🏢 Working client vault with populated `00-PROFILE/` and datamodel folders
- 📋 Core playbook bundle running on cadence with KPI history
- 📊 Decision log and approval/audit records
- 📊 Quarterly Refresh Report.md and Governance Report (PDF)
- 📝 Renewal decision log (`renew` / `renew-expand` / `non-renew`)
